# Проверка Hausman for Home Assistant 1.52.233

Ограниченное дополнение к 1.52.232: точный текст результата отложенного
прибора соответствует API v1. Новые записи используют канонический текст.
Прежняя проверенная квитанция получает его только в копии HTTP-ответа.
Подписанная история, статусы, счётчики, доказательства и команды не меняются.

Самостоятельное ревью Codex подтвердило узкие условия нормализации:
точный прежний текст, deferred/device_unavailable/deferred_offline, отсутствие
execution_state и два строго целочисленных нуля. Неизвестный текст,
повреждённые поля или ненулевые команды не исправляются автоматически.
Доступ и проверка подлинности истории выполняются до преобразования.

Проверено:

- Новая регрессия воспроизвела нарушение схемы до исправления. После правки
  проходит строгая проверка принятого и конечного ответа общей цели с
  выключенным температурным прибором и ненужной старой влажностью.
- Три HTTP-пути возвращают канонический ответ, не меняя исходную квитанцию.
  Семь вариантов других полей остаются неизменными, включая логический
  счётчик, ненулевую принятую команду и неизвестное сообщение.
- Полный pytest: 2878 PASS, 4 штатно пропущены. Полный local release PASS:
  2321 unittest, отдельные проверки архива, fixtures, совместимости,
  версии, наименований, состава пакета и границ публикации.
- Критическое покрытие: 75% при пороге 75%, 344 теста PASS.
- Комплект VERIFIED_LOCAL: все 981 файл и их права совпадают с исходниками.
- Браузер: 50 PASS, 735 состояний элементов, 708 действий и 43 исходные
  точки. Ошибок, непредусмотренных запросов и выхода в живую сеть нет.

Contracts 0.65.0 и private Android 1.0.277 совместимы, код клиента не менялся.
Frontend содержит только точную замену номера кеша. GitHub 34308045860 PASS
на точном 097c13c. Выпуск опубликован и установлен: 600 файлов и панель
совпали, конфигурация и один перезапуск PASS. Старую операцию перечитали:
строгая схема квитанции PASS, цель сохранилась, подписанная запись не менялась.

Полное физическое применение не заявляется: два прибора подтвердили по
одной команде, четыре ручных и два отложенных получили ноль вызовов.
Повторная отправка и включение приборов для приёмки не выполнялись.

Отдельное ограничение: расширенный live runtime не соответствует своей
схеме из-за дополнительных desired-полей и отсутствующих старых target-полей.
Присваивания существуют с 4c2dce02 / 1.52.196 от 31 августа, в этом выпуске
не менялись. Полный аудит схемы runtime получил FAIL, 77 нарушений на
проверенном ответе. Это не проверка квитанции, которая получила PASS.
Прежняя блокировка миграции сценариев также остаётся вне области ремонта.
