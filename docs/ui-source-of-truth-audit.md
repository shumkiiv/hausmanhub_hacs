# Единый источник истины интерфейса

Аудит 2026-08-01 сравнил навигацию Android, HACS и два рабочих файла Figma.
Машиночитаемая матрица находится в
[`ui-source-of-truth-audit.json`](ui-source-of-truth-audit.json).

## Правило синхронизации

1. Фактическое поведение приватного Android-приложения сверяется с продуктовым
   файлом Figma `4vaAkBsKwtSyqJrr2X5RRs`.
2. Если Android новее макета, сначала обновляется и явно помечается продуктовый
   `CANON`-фрейм. Старый фрейм получает префикс `ARCHIVE /`.
3. Для HACS используется тот же shared `CANON`, перенесённый в файл
   `UK1PgZUQQrvYJ7tRZzWyvo`; только после этого меняется код панели.
4. Фреймы с префиксом `ARCHIVE /` не являются техническим заданием и не могут
   быть реализованы повторно.

Так Figma остаётся источником истины, но уже хорошо работающий Android не
теряется из-за случайного выбора устаревшего макета.

## Результат аудита

Навигация Android и HACS совпадает по десяти основным разделам: Главная,
Освещение, Климат, Комнаты, Медиа, Безопасность, Устройства, Энергия, Сценарии и
Настройки. Режим киоска является отдельным представлением Главной.

В продуктовом Android-файле существуют отдельные canonical-экраны для всех
разделов. В HACS-файле подтверждённый shared `CANON` уже есть для Энергии,
Сценариев и Киоска. Фрейм Климата существует, но ещё требует визуальной сверки с
текущим Android перед признанием общим каноном. Для Освещения, Комнат,
Безопасности и Устройств shared-канон отсутствует; Медиа имеет только карточку
телевизора; Главная и Настройки также требуют сверки с текущим Android.

Поэтому визуальная переработка HACS выполняется в следующем порядке:

1. очистить структуру двух файлов Figma и отделить `CANON` от `ARCHIVE`;
2. зафиксировать общие tokens/components;
3. синхронизировать Главную и shell;
4. последовательно перенести остальные функциональные разделы по матрице.
