# Hausman Hub HACS 1.52.216: аудит срочного исправления запуска сценариев

Дата подготовки: 2026-09-05.

## Причина выпуска

Версия 1.52.215 была установлена в production, но первый каталог Home Assistant
оказался неполным. Проверяемая миграция не нашла один из целевых идентификаторов,
безопасно остановилась и не изменила три живых системных сценария. Новые
обработчики выключателей также не запустились. После этого production был
возвращён на 1.52.214.

## Исправление

- Миграция сначала проверяет наличие всех целевых устройств и повторяет попытку
  только на следующих снимках штатного ограниченного прогрева каталога.
- Последняя неполная попытка фиксирует `catalog_retry_exhausted` и оставляет
  расписание, события состояния и обработчики клавиш выключенными.
- После успешной CAS-миграции зависимые обработчики запускаются один раз.
  Повторный снимок каталога не создаёт вторые подписки.
- Выгрузка интеграции снимает наблюдателя и отменяет задачу прогрева, поэтому
  поздний снимок старого поколения не может запустить физическую команду.
- Отмена после уже выполненной записи Node-RED сначала завершает точную
  компенсацию источника и хранилища, затем возвращает отмену вызывающему коду.
- Обратные вызовы очистки расписания и событий собираются в одном наборе до
  полного запуска. Отмена закрывает право выполнения первой, снимает все
  частичные подписки и не публикует готовность.
- Чтение release-owned JavaScript выполняется через исполнитель Home Assistant,
  а не в основном цикле событий.

## Климатическая регрессия

Добавлена отдельная проверка смешанной общей цели: подтверждённый работающий
прибор и два недоступных владельца сразу дают финальный `partial` с
`saved_deferred_offline`. Полное 30-секундное окно не ожидается, повтор запроса
не отправляет команду заново. Производственный код климата не менялся, потому
что проверка прошла на существующей реализации.

## Границы кандидата

- Контракты API и формат ответов для Android не меняются.
- Состав трёх мигрируемых сценариев, их хэши и CAS-семантика не меняются.
- Физические проверки устройств в подготовку кандидата не входят.
- Полные выпускные проверки, публикация, установка и живая проверка фиксируются
  корневым координатором после прохождения следующих этапов цепочки.
