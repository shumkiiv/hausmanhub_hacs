# Консолидация сценариев Hausman Home: план реализации

**Цель:** безопасно заменить пересекающиеся сценарии восемью контроллерами,
не допуская физических команд до проверяемой атомарной миграции.

**Основание:** `docs/superpowers/specs/2026-09-07-hausman-scenario-consolidation-design.md`
и расширенные требования владельца от 2026-09-07.

## Статус

Первые общие primitives добавлены commits `1cd1d5a` и `8dbccc0`, но план не
готов к выпуску. После единственного repair тестировщик остановил цепочку:
пять новых controller source пока не зарегистрированы в production runtime.

### Уточнение 2026-09-07

Новая read-only проверка сняла блокировку доступа: маршруты
`/api/hausman_hub/v1/admin/scenarios*` доступны настоящему локальному
администратору и дают полный inventory из 58 сценариев. Обычные
`/v1/scenarios*` остаются intentionally tablet-only и не должны получать
административные права. Реализация использует административный маршрут для
снимка и миграции, не меняя публичную политику авторизации.

Все восемь controller source должны стать trusted production sources в
`custom_components/hausman_hub/managed_scenarios/`. Пять файлов в `tools/`
не являются исполняемой реализацией. Их положительные ветки должны пройти
через типизированный исполнитель, production envelope и атомарную migration.
Переходы яркости выполняются серверным coordinator по generation, а не
сотнями отложенных действий из Node-RED.

Порог кухни 80% и кабинета 90% проверяется относительно полного физического
хода после подтверждения соответствия шкалы. Если для такого соответствия
нужна рекалибровка, перед первым движением запрашивается подтверждение
владельца, который наблюдает штору. До этой точки остальные программные
изменения и тесты не ждут.

## Возобновление

1. Получить точный read-only snapshot всех live definitions, sources,
   bindings, revisions, enabled-state и пересекающихся native HA automation.
   Остановиться, если snapshot нельзя получить через авторизованный
   безопасный маршрут.
2. Составить и зафиксировать полный manifest: каждая прежняя automation
   должна иметь ровно одно решение - новый контроллер, защищённое сохранение
   либо удаляемый отключённый дубль. Защиту воды, автоматы и аварийные
   правила из manifest исключить.
3. Реализовать и RED/GREEN-проверить все восемь production controller
   sources в `custom_components/hausman_hub/managed_scenarios/`: тамбур,
   малый коридор, душевая, туалет, ванная, кладовка, кабинет, шторы.
   `tools/managed_scenarios/` не считать исполняемым источником.
4. Подключить OR-evidence, расписание Asia/Omsk, 30-секундный подъём,
   относительное снижение 10% за пять минут, CT и ручной приоритет к
   исполняемым sources. Проверить motion-only, presence-only, оба типа,
   unavailable и отмену каждого pending transition.
5. До реализации curtain cap подтвердить шкалу: новые 80%/90% задаются от
   полного физического хода или от текущей уже перенормированной шкалы HA.
   После ответа проверить конкретное руководство TS0601 и только затем
   планировать калибровку кабинета.
6. Расширить CAS migration: prepare, exact compare, stage без listeners,
   verify, activation одним generation, completed receipt и exact rollback.
   Добавить fault injection после каждой фазы и защиту от конкурирующих
   native HA automation.
7. Завершить профильные, release и browser проверки. Только после PASS
   запускать reviewer и security audit.
8. После всех gate выполнить backup, release и controlled migration. Затем
   провести физические тесты с Яндекс-объявлением перед каждым действием,
   исключив воду и автоматы, и восстановить исходное состояние.

## Блокеры

- API сценариев, доступный текущим credentials, отвечает 403: отсутствует
  свежий полный snapshot для exact manifest.
- Не выбрана физическая шкала новых пределов открытия кухни и кабинета.
- Увлажнитель гостиной недоступен: его физическая приёмка закрыта до
  восстановления связи.
