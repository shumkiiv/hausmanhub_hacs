# Локальные привязки ручных выключателей

Дата: 2026-09-10.
Статус: согласовано владельцем для реализации.

## Цель

Убрать постоянные идентификаторы устройств конкретного дома из публичной
интеграции Hausman for Home Assistant. Сохранить проверяемые смыслы нажатий
и защиту от повторов, но получать идентификаторы выключателей только из
локального хранилища Home Assistant.

## Границы

- Публичный код хранит только фиксированные профили и разрешённые подтипы:
  `shower`, `passthrough`, `marmitek`.
- Локальная запись хранит соответствие профиля и HA device ID. Она не
  содержит MQTT-топиков, произвольных действий или названий сервисов.
- Настройка, перенос и чтение записи не подписываются на события, не
  запускают перенос тамбура и не отправляют физические команды.
- Android, публичный API, контракт и Node-RED decision contract не меняются.
- При отсутствии, повреждении, восстановлении старой версии, неполном наборе
  либо неоднозначной привязке ручной контур тамбура не подключается. Нельзя
  искать устройство по имени, модели или похожему набору кнопок.
- Общая миграция сценариев, пользовательские шторы, климатика и другие
  комнаты остаются вне задачи.

## Локальная запись

Файл Home Assistant Store:
`hausman_hub.smart_switch_bindings.<entry_id>`.

```json
{
  "version": 1,
  "revision": 1,
  "devices": {
    "shower": "<local-ha-device-id>",
    "passthrough": "<local-ha-device-id>",
    "marmitek": "<local-ha-device-id>"
  }
}
```

`revision` - положительное целое. Идентификатор непустой. Один ID не может
быть назначен разным профилям, кроме двух смыслов одной записи `marmitek`.
Неполная запись допустима как сохранённая настройка, но не разрешает запуск
тамбурного ручного контура.

## Поведение адаптера

Адаптер получает уже разрешённый список trigger-конфигураций, где каждый
элемент содержит профиль, смысловую привязку, точный HA device ID и один из
жёстко заданных подтипов. Он больше не строит конфигурации при импорте и не
выводит смысл нажатия из глобальных констант устройства.

Разрешённая таблица не меняется:

| Профиль | Привязка | Подтипы |
| --- | --- | --- |
| shower | shower-cabinet | toggle_b2_down, on_b2_down, toggle_b2_up |
| passthrough | tambur-light-group | on_down, toggle_down, off_up |
| marmitek | tambur-mirror-left | 1_single, 1_double |
| marmitek | tambur-master-off | 2_single, 2_double |

Перед подпиской проверяются запись, локальный реестр устройств и точные
device automation trigger configs. Ошибка закрывает только ручной контур и
не передаёт управление комнатой. После чтения следующая попытка запуска
возможна только через уже существующий контролируемый путь.

## Перенос и настройка

Старый публичный код не сохранял привязки. Перед обновлением прежняя
установка должна локально извлечь её активные значения из своего рабочего
состояния, проверить по локальному реестру и сохранить новую запись. Если
доказанного источника нет, автоматический перенос прекращается, а владелец
выбирает устройства локально. Значения не попадают в журнал, тесты,
исходники или документацию.

Изменение привязок сохраняет только новую локальную запись. Для применения
нужен отдельный контролируемый запуск, а не автоматический reload.

## Ошибки и безопасность

- Невалидная или восстановленная запись: нет подписок, нет команд.
- Конфликт revision: сохранение отклоняется, действующая запись не меняется.
- Устройство или точный trigger не подтверждён: нет подписок, нет команд.
- Неудача снятия подписок старого поколения: новое поколение не включается.
- Receipt дедупликации сохраняет прежний формат и не получает device ID.

## Обезличенная проверка встроенной автоматики

Публичная фикстура встроенной автоматики использует синтетический
идентификатор выключателя. Рабочее определение Home Assistant содержит
локальный идентификатор, поэтому перед расчётом публичного хэша допускается
ровно одно условное преобразование.

- При запуске загружается один неизменяемый проверенный объект
  `SmartSwitchBindings`. Этот же объект передаётся адаптеру кнопок и проверке
  встроенной автоматики. Хранилище не перечитывается во время проверки.
- Преобразование допустимо только для целевой автоматики зеркального
  выключателя и только после нормализации существующих alias-полей.
- В рабочем определении должны быть ровно два разрешённых события левых
  нажатий, в заданном порядке и с точными ключами trigger-конфигурации. Оба
  их локальных идентификатора должны в точности совпадать с `marmitek` из
  переданного объекта привязок.
- Только в проверенной копии этих двух полей локальный идентификатор заменяется
  синтетическим значением публичной фикстуры, затем хэшируется всё определение.
  Исходный ответ Home Assistant не изменяется.
- Отсутствующая, восстановленная, неполная или несовпадающая привязка, лишнее
  событие, иной подтип, порядок, ключ, действие или цель останавливают
  миграцию до передачи управления. Никакие другие поля и автоматизации не
  нормализуются.
- Сохранение новой записи не меняет уже работающее поколение. Для её применения
  по-прежнему нужен отдельный контролируемый запуск.

## Приёмка

1. В публичном исходном коде, тестах, фикстурах и новых документах нет
   идентификаторов конкретных домашних выключателей.
2. Валидная синтетическая локальная запись строит только разрешённые exact
   triggers и сохраняет текущую семантику и дедупликацию.
3. Пустая, повреждённая, устаревшая или неполная запись не запускает ручной
   контур и не начинает миграцию тамбура.
4. Сохранение и перенос привязок не вызывают Home Assistant services.
5. Новые unit и integration tests проходят вместе с независимым ревью и
   security audit. Полный набор требует отдельного разрешения владельца.
6. До локальной подготовки записи публикация и установка не выполняются.
7. Два синтетических рабочих определения с разными синтетическими локальными
   привязками проходят одинаковую публичную проверку только при точном
   совпадении с переданным `marmitek`; любое несовпадение блокируется.
