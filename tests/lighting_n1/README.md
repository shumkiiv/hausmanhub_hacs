# N1: проверка точного установленного пути света

Связь: HH-014.b / HH-015.a, stage lighting-n1-verification-20261014.
Это диагностический тест, не новая автоматика. Текущий V01 намеренно
сохраняет обычный FAIL, без xfail/skip: обнаружена ложная ручная запись
после подтверждённого собственного ON. FAIL нельзя принимать как выпуск.

## Повторение

Запускать из этого integration worktree в двух отдельных процессах.
Стандартный Python3.12; существующая cryptography используется из системного
каталога. Home Assistant не установлен и не устанавливается этим тестом.

```sh
env -i PATH=/usr/local/bin:/usr/bin:/bin PYTHONDONTWRITEBYTECODE=1 \
  python3 -m unittest discover -s tests/lighting_n1 -p test_ports.py -v

env -i PATH=/usr/local/bin:/usr/bin:/bin PYTHONDONTWRITEBYTECODE=1 \
  N1_CANDIDATE=/home/ivsh/projects/Hausman/work/hh014b-live-20261013/force-auto-r3/candidate \
  N1_ORACLE=/home/ivsh/projects/Hausman/docs/product/roadmap/evidence/lighting-model-20261013/model \
  python3 -m unittest discover -s tests/lighting_n1 -p test_installed_path.py -v
```

Смешанный запуск всего tests/lighting_n1 не поддерживается: барьеры аудита
процесса необратимы, каждый запуск имеет своё временное хранилище. После
единственного теста оно удаляется. Домашние access-файлы не нужны.
Путь снимка можно передать иной, но его точный состав обязан соответствовать
заранее закреплённому fingerprint, иначе импорт отвергается.

## Настоящий путь и внешние подмены

Из неизменного снимка импортируются async_setup_entry, реальные подписки,
четыре участника ручных прав, комнатный writer, HTTP-обработчик возврата,
сохранение координаторов, расчёт, HA executor и повторный startup.
Ни один метод Hausman не подменяется и не вызывается вместо штатной оценки.
Частные журналы только читаются для проверки.

Внешние порты заменяют framework HA: bus/state machine, регистрацию
платформ, ConfigEntry, Request/HTTP-ответ, Store, native transport и часы.
Store действительно пишет отдельные JSON-файлы через fsync/replace;
это не проверка настоящего HA Store или аварийного отключения питания.
Настоящие VerifiedSafetyStore, проверка ревизий и прикладные сохранения
работают поверх этого внешнего порта без изменений.

Источник SUT проверяется до импорта и после сценария: ровно514 файлов,
каждый SHA256, manifest fingerprint
2800211a415719a8ca2f21f9e1370578a42fefbdc7e3592788a8ca73e296bd59.
База worktree12636e9 служит только местом тестов, не источником SUT.
Эталон P1 закреплён отдельным SHA256, не импортирует программу и получает
фиксированные синтетические условия, а не вычисленную программой цель.

## Сценарий

1. Реальная загрузка, ручной ON и OFF с контекстом синтетического пользователя.
2. Реальный unload/setup из сохранённых файлов. Presence остаётся ON,
   после startup поступает свежий внешний report с force_update=True.
   Старый report до границы startup правильно блокирует возврат.
3. Авторизованный внешний вход HTTP-обработчика force-auto.
4. Одна настоящая отправка light.turn_on60%/4000K, свежий полный report с
   тем же контекстом, подтверждённое комнатное AUTO.
5. Сравнение с неизменным эталоном: новое manualBlocked недопустимо.
6. Вызов зарегистрированного минутного callback при неподвижном presence,
   цель меняется на40%/3000K. Это не ручной вызов async_process.
7. Повторный unload/setup из тех же файлов показывает перенос ложного
   manual в общий блокирующий слой. В конце сравнение остаётся FAIL.

## Границы

Проверки test_ports доказывают только свойства стенда и чувствительность
сравнения. Не доказывают пригодность света, настоящий HTTP middleware,
интерфейс HACS/Android, Zigbee2MQTT или физическое устройство.

Wall clock datetime/time/time_ns виртуальный. Asyncio monotonic/sleep
не виртуализированы; полного симулятора суток/всех таймеров здесь нет.
Стенд запускает один зарегистрированный календарный callback, не полный
календарь HA. State port всегда публикует state_changed, включая неизменное
значение; свежий report перед возвратом явно force_update=True. Основной
кодовый дефект наблюдается на настоящем OFF->ON с изменением значения.
No-op/state_reported/reconnect и независимая загрузка каждой HA-платформы
не проверены. Независимый background catalog warmup не ожидается в drain;
он остаётся настоящим и останавливается штатными callback unload.

Сетевые сокеты INET/INET6, connect/sendto/DNS, subprocess и os.system
запрещены. Чтение ограничено снимком, эталоном, тестами и библиотеками;
запись ограничена временным хранилищем. Это барьер доверенного Python-теста,
не защищённая ОС-песочница для произвольного вредоносного кода.

Остальные A/B/C/D, незавершённый старый writer, гонки ручного действия,
отказы сохранения/ответов и полные сутки не объявляются пройденными:
основной V01 завершился воспроизводимым расхождением программы.
Никаких команд дому, установки, полного набора тестов или push.
