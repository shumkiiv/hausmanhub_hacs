# Hausman Hub

Hausman Hub — система автоматических контуров дома в виде интеграции Home
Assistant. Сейчас развивается первый контур — климат: комнаты связываются с кондиционерами,
термоголовками, увлажнителями, тёплым полом и датчиками. Позднее на той же
основе можно добавить освещение, воду, безопасность и энергию.

**HACS** — это не название проекта, а каталог, через который Hausman Hub можно
установить и обновлять в Home Assistant.

Текущая версия - **1.52.212**.

Инструкция безопасного перехода на самостоятельный runtime Home Assistant:
[`docs/migration-1.52.0.md`](docs/migration-1.52.0.md).

## Защита журнала климатических команд

В Home Assistant OS дополнительная настройка не нужна. При первом запуске
Hausman Hub сам создаёт закрытый keyring-файл
`/media/hausman_hub/climate-ledger.json` с правами доступа только для владельца.
Каталог `/media` сохраняется отдельно от конфигурации Home Assistant, поэтому
ключ не попадает в ConfigEntry или `.storage`. Не удаляйте этот файл и
включайте каталог `/media/hausman_hub` в резервную копию вместе с Home Assistant.
Он защищает журнал от подмены файлов в `config` и `.storage`, но не заменяет
защиту учётной записи администратора Home Assistant и её полных резервных копий.

На Home Assistant Container и Supervised путь задаёт администратор через
переменную окружения `HAUSMAN_HUB_CLIMATE_LEDGER_KEYRING_PATH`. Это должен быть
абсолютный путь вне каталога конфигурации Home Assistant к обычному файлу с
правами `0600`. Такой же путь можно использовать в Home Assistant OS, если
нужно хранить ключ во внешнем менеджере секретов. Пример содержимого файла без
настоящих ключей:

```json
{
  "active_key_id": "2026-09",
  "keys": {
    "2026-09": "64 символа шестнадцатеричного ключа",
    "2026-08": "предыдущий 64-символьный ключ на время ротации"
  }
}
```

Активный ключ подписывает новые записи. Предыдущий ключ остаётся в файле только
пока Home Assistant не перечитает и не переподпишет нужные записи. Путь и ключи
не добавляйте в конфигурацию интеграции, `.storage`, Git, журнал или резервную
копию проекта. Если keyring недоступен или запись не проходит проверку,
надёжный контур климатических команд остаётся недоступным.

Для Container и Supervised создайте этот JSON-файл на локальном носителе вне
`config` Home Assistant, назначьте владельца процессу Home Assistant и права
`0600`, затем передайте его абсолютный путь через переменную окружения сервиса.
Например, для systemd:

```ini
[Service]
Environment="HAUSMAN_HUB_CLIMATE_LEDGER_KEYRING_PATH=/var/lib/hausman-secrets/climate-ledger.json"
```

После изменения переменной перезапустите Home Assistant. Первый запуск с новым
keyring намеренно удаляет прежний локальный журнал климатических операций,
включая сохранённые квитанции и восстановление управления. Это безопасный
старт с чистого листа: старые flat-файлы и вложенная история планшета не
читаются и не импортируются. Новый пустой журнал получает внешний якорь в
keyring. Не удаляйте поле `ledger_anchors`, которое появится в файле после
первой записи: оно обнаруживает откат или согласованную подмену локальных
файлов.

Для ротации добавьте новый 64-символьный hex-ключ в `keys`, сделайте его
`active_key_id`, перезапустите Home Assistant и дождитесь новой климатической
операции. Старый ключ сохраняйте, пока все нужные старые записи не будут
переподписаны, затем удалите его отдельным изменением keyring и снова
перезапустите Home Assistant. Храните отдельную защищённую резервную копию
keyring вместе с его `ledger_anchors`. При восстановлении возвращайте эту пару
и соответствующие локальные файлы журнала из одной точки во времени. Если
якорь и локальные файлы не совпадают, не удаляйте якорь для обхода проверки:
начните новый журнал с новым keyring или восстановите согласованную резервную
копию.

### Что важно сделать после обновления

1. Пользователям Home Assistant OS достаточно обновить Hausman Hub через HACS
   и перезапустить Home Assistant. Файл keyring появится автоматически.
2. До обновления сделайте обычную резервную копию Home Assistant. После
   обновления проверьте, что существует `/media/hausman_hub/climate-ledger.json`.
   Не открывайте и не публикуйте его содержимое.
3. При использовании Container или Supervised сначала создайте внешний файл
   keyring, передайте его в контейнер с правами `0600`, задайте переменную
   окружения и только затем перезапускайте Home Assistant.
4. Первый безопасный запуск начинает чистую историю надёжных климатических
   команд. Старые незавершённые климатические операции и квитанции не
   переносятся и не повторяются. Это защита от повторной физической команды.
5. Если keyring потерян или изменён, не продолжайте наугад. Остановите
   климатические команды, восстановите прежний `/media/hausman_hub` или внешний
   файл из защищённой копии и затем перезапустите Home Assistant.

## Что умеет текущая версия

- Единый снимок дома: `GET /api/hausman_hub/v1/home` возвращает комнаты,
  устройства, цели климата и состояние контура одним ответом. Русские
  названия режимов, причин и состояний приходят в `display_names`, а для
  каждой комнаты отдельно сообщается, какие действия доступны прямо сейчас.
- Живые события: поток `GET /api/hausman_hub/v1/events` с heartbeat,
  объединением частых изменений и восстановлением по `Last-Event-ID`. В нём
  же приходят тревоги, низкий заряд и квитанции команд. Периодический опрос
  остаётся резервным каналом.
- Строгие команды: клиент может вызвать только разрешённый набор действий,
  без произвольных сервисов и внутренних идентификаторов. Результат -
  честная квитанция (подтверждено наблюдением, ожидает, частично,
  недоступно), а повтор запроса возвращает прежний результат, не дублируя
  команду.
- Быстрые сценарии с Hausman AI: пользователь описывает правило обычными
  словами, вставляет конкретные устройства через `@` или диктует текст.
  Сервер возвращает только проверенный выключенный черновик либо вопросы,
  ничего не сохраняет и не запускает без пользователя.
- Связи питания: люстру или другое устройство можно связать с выключателем либо
  реле. Hausman Hub при необходимости включает источник, подтверждает питание,
  ждёт заданную задержку и затем отправляет исходную команду. Источник остаётся
  включённым, поэтому зависимое устройство сохраняет связь с сетью даже в
  логически выключенном состоянии.
- Климат по комнатам: цели температуры и влажности, профили «День» и «Ночь»,
  расписание по местному времени, временная температура с возвратом к
  расписанию. Режимы `disabled`, `shadow`, `canary`, `managed` ограничивают
  управление поэтапно. Автоматический обогрев выключается по порогам улицы,
  кондиционеры защищаются от запуска на морозе, а межсезонный режим
  сдерживает слабую нагрузку.
- Энергия: карточки физических источников с мощностью, током, напряжением и
  накопленной энергией, до 16 независимых счётчиков, календарная статистика
  Recorder и настраиваемая тревога длительного высокого потребления.
  Настройка хранится в Home Assistant и поэтому одинакова для панели и
  планшета.
- Панель в боковом меню Home Assistant: главная сводка, климат, комнаты,
  устройства, энергия, безопасность, сценарии, медиа, освещение и настройки.
  Устаревшая форма получает HTTP 409 и понятное предложение повторить, а
  фоновое обновление не затирает редактируемые значения.
- Безопасная миграция настроек из Node-RED: локальный preview отделяет
  переносимые цели от runtime-состояния и секретов, атомарный apply требует
  явное сопоставление комнат и не отправляет команды устройствам.
- Проверка перед управлением: redacted shadow-сравнение нативного плана с
  наблюдаемым поведением действующего контура хранит окно в семь суток и
  выдаёт вердикт готовности каждой комнаты. Мастер «Привязки» сопоставляет
  логические устройства с сущностями Home Assistant только вручную.
- Планшетное приложение Hausman (Android, закрытое тестирование) работает по
  этому же локальному API и показывает ту же модель дома.

## Как теперь устроен климат

Отдельная страница **Hausman Hub** в боковом меню — основное место настройки и
управления климатом. На ней видны состояние и комнаты, переключается режим
управления, задаются профили «День» и «Ночь», расписание, сигналы дома и
сигналы комнат, применяются сохранённые настройки и временная
температура. Страница работает через строгие локальные API: устаревшая форма
получает HTTP 409 и честное предложение повторить, а фоновое обновление не
затирает редактируемые значения. Мастера **Hausman Hub → Настроить** остаются
запасным путем, в том числе для первоначального создания контура.

Обычная настройка выглядит так:

1. Открыть **Hausman Hub → Настроить → Климат**.
2. Выбрать **Выбрать комнаты и климатические устройства**.
3. Пока идёт перенос алгоритма, один раз указать локальный адрес уже работающей
   системы климата. В самостоятельной версии этот шаг исчезнет.
4. Отметить комнаты и находящиеся в них кондиционеры, термоголовки,
   увлажнители, тёплый пол и датчики.
5. Для каждой выбранной комнаты отдельно задать комфортную температуру,
   влажность и характер работы.
6. Проверить понятное резюме и сохранить настройки.
7. Выбрать **Задать настройки для дня и ночи** и задать
   два набора комфорта для каждой комнаты.
8. Выбрать **Настроить автоматическое расписание**, указать начало дня и ночи
   и подтвердить постоянное разрешение.
9. После этого Hausman Hub сам переключает дневные и ночные настройки по местному
   времени Home Assistant и передаёт их подключённой системе климата.
10. Если до следующего переключения нужно сделать комнату теплее или холоднее,
    выберите **Временно изменить температуру в комнате**. Для досрочного
    возврата выберите **Вернуть температуру по расписанию**.

В обычном мастере показываются только понятные названия комнат, устройств и
действий. Служебные средства находятся в разделе
**Диагностика и обслуживание**.

В разделе **Окружение дома** можно подключить датчик наружной температуры,
общий сигнал присутствия дома и центральное отопление. Там же задаются пороги, при которых
автоматический обогрев выключается и разрешается снова. Если сигнал не выбран,
он не участвует в расчёте.

Здесь же задаётся критический минимум наружной температуры для кондиционеров
(по умолчанию −5 °C). При достижении порога Hausman Hub запрещает автоматический
запуск и безопасно выключает работающий кондиционер, даже если его включили
вручную. Защита действует только при доступном числовом показании выбранного
уличного датчика или погодного сервиса и не выключает отопительные устройства.
Когда выбранный физический датчик присылает свежие показания (не старше 10
минут), климат опирается на него, а погодный сервис служит перекрёстной
проверкой; при молчании датчика используется сервисная температура.

В разделе **Сигналы комнат** для каждой комнаты отдельно выбирается датчик
окна и любое количество бинарных датчиков присутствия. Один комнатный датчик
присутствия нельзя одновременно назначить нескольким комнатам. Общий сигнал
дома остаётся отдельным и продолжает определять режим «дома/вне дома»;
мгновенное отсутствие движения в комнате само по себе не меняет её целевую
температуру.

## Установка через HACS

1. Откройте **HACS** в боковом меню Home Assistant.
2. В меню с тремя точками выберите **Пользовательские репозитории**.
3. Добавьте `https://github.com/shumkiiv/hausmanhub_hacs` с типом
   **Интеграция**.
4. Найдите **Hausman Hub**, нажмите **Скачать** и перезапустите Home Assistant.
5. Откройте **Настройки → Устройства и службы → Добавить интеграцию**, найдите
   **Hausman Hub** и оставьте режим **Обычный режим — рекомендуется**.

Подробная пошаговая инструкция, обновление и решение частых проблем описаны в
[руководстве по установке Hausman Hub через HACS](docs/install-via-hacs.md).

Если новый компьютер не доверяет локальному HTTPS-сертификату, используйте
[безопасный сценарий доступа](docs/secure-local-access.md). В нём есть шаги
для Windows и правило проверки отпечатка корневого сертификата.

Установка и обновление сами по себе не настраивают живой климат и не отправляют
команды. Право на применение появляется только у сохранённого автоматического
контура и всё равно требует отдельного подтверждения.

## Разделы настроек

- **Климат** — основное место настройки комнат, устройств, дневных и ночных
  значений и расписания.
- **Информация о доме** — девять обезличенных диагностических счётчиков и
  частота их обновления; на климат не влияет.
- **Диагностика и обслуживание** — подключение, перенос старых настроек и
  служебные проверки. Для обычной работы они не нужны.

Подробная схема описана в [руководстве по климатическому
контуру](docs/climate-control-architecture.md), а проверка установки — в
[инструкции для Home Assistant](docs/home-assistant-safe-check.md).

## Безопасность

Hausman Hub не хранит в репозитории ключи, пароли, адрес дома, реальные идентификаторы
устройств или снимки настроек. Контур принимает только локальный HTTP(S)-адрес
с буквальным частным IP. Публичные адреса, перенаправления, имена сайтов, пути,
параметры, логины и пароли отклоняются.

Приложение планшета не может передать произвольный сервис Home Assistant,
внутренний идентификатор устройства, адрес или команду нижнего уровня.
Пределы очереди, защита от дребезга, единый снимок условий и redacted журнал
описаны в [руководстве по безопасности сценариев](docs/scenario-safety.md).

## Для разработчиков

Полная локальная проверка:

```shell
python3 tools/check_local_release.py
```

Она использует синтетические данные, не подключается к дому и не отправляет
команды устройствам. Правила разработки описаны в
[CONTRIBUTING.md](CONTRIBUTING.md) и
[инженерных требованиях](docs/engineering-standards.md).

Codex выполняет финальный self-review окончательного текущего набора изменений.
Перед коммитом, отправкой, выпуском, развёртыванием или публикацией проверяются
staged diff, профильные тесты и полный local release gate.
